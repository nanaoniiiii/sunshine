# 编码队列、编码器选项与远程唤醒

v2026.10.12.4 延续 foundation-sunshine 的逐会话控制思路，以及固定 connect-screen.com Android 原生移植。保留现有 Moonlight 协议与上一版默认关闭的自适应控制，不移植桌面显示驱动。

## 编码队列

每个客户端最多排队 8 帧、8 MiB；入队与出队检查 80ms 驻留期限。超限时清除该客户端的参考帧链，拒绝后续依赖帧，等待新 IDR，恢复请求最多每秒一次。另一个客户端的帧链不因此被清除。退出释放队列中的会话引用；回调与丢弃帧的析构在队列锁外执行。

期限限制排队驻留，不包括已经出队的编码帧、内核发送等待或端到端延迟。一个过大的关键帧按平均码率发送可能超过期限，造成重复 IDR/丢帧循环；因此 IDR 允许有限的短时发送加速：估算包头、FEC 后以约 40ms 为目标，加速上限 80Mbps（已有更高的基础 pacing 保留），普通帧继续按会话预算 pacing。编码码率/FEC 名义预算不变，但瞬时发送速率可以超过平均预算；实际慢链路仍可能阻塞，不能保证所有关键帧在 40ms 内完成。

## 编码器选择

设置分别列出 H.264 与 HEVC 编码器，标明系统提供的硬件/软件分类。`encoder_h264`、`encoder_hevc` 默认为 `auto`，保存后用于新连接。Auto 首先调用系统 `createEncoderByType`；创建、配置、输入 Surface 或启动失败后，清理候选资源，再按枚举顺序尝试其余同格式编码器，排除已尝试的实际组件名。默认编码器成功就不会尝试其他组件，没有设备型号排名规则。

指定组件名时只尝试该组件，失败后显示错误与“切换编码器”入口，不悄悄替换。允许保留已经不可用的旧选择，并提示更换。启动后的运行时编码器错误同样提示切换；本版不进行连接中热替换。自动失败遍历由独立策略测试覆盖，真机验证了正常默认组件、明确组件与不存在的明确组件，未人为破坏平台默认编码器。

Release 混淆保留 Retrofit 响应及协程的泛型签名，修复设置请求因泛型被裁剪而失效的问题。

## 反馈控制

孤立可恢复丢失先观察。两秒窗口内至少三次损失块报告，或两次不可恢复块报告，且跨度至少 200ms，才触发损失回退；单个不可恢复块缺失达到 20% 可立即反应。保留两秒控制冷却、驱动确认和名义预算限制。

持续队列压力（年龄至少 40ms 或深度至少 3，四次以上采样且跨度至少 500ms）及持续一秒的异常控制 RTT，可降低编码码率约 10%，不因此增加 FEC。探升还要求近期低队列压力和新鲜健康 RTT。ENet RTT 是控制通道平滑测量，五秒内的控制收包用于判断新鲜度，不是视频到屏幕的时延。手动控制仍退出自适应模式。

## 新诊断

`GET /api/diagnostics` 的 `video` 列表新增编码器选择/尝试次数、可空的驱动延迟提示、队列深度/字节/峰值/丢弃/等待 IDR、发送数据与 parity 包计数、UDP payload 字节与速率、发送失败计数，以及队列、FEC 计算、pacing 等待、socket 发送、整帧发送 P95。窗口最多 256 样本。

发送计数表示内核接受的 UDP payload，不证明客户端接收；不包含 IP/UDP 头和独立音频流。`actual_parity_ratio` 是已接受 parity 包数/数据包数，不是丢包率。socket/send P95 不是网络往返或端到端时延。损失报告覆盖边界沿用 [网络反馈说明](network-feedback.md)。

## Moonlight 操作唤醒

在已有串流中，远程鼠标、滚轮、键盘、文本、触摸和笔输入可请求亮屏。引擎回调最多每 250ms 一次；宿主只在屏幕非交互且仍有串流时请求，失败重试至少间隔一秒。先通过已授权 Shizuku 的电源 Binder 请求唤醒，接口不兼容时使用同一授权注入 `KEYCODE_WAKEUP`，不使用会切换回息屏的电源键。Shizuku 断开时清除代理缓存。

这依赖设备允许 Shizuku 注入；唤醒不关闭系统安全锁屏，不输入密码，不自动解除锁屏。OPPO Android 11 已验证兼容唤醒键路径；其他厂商仍需真机验证。
