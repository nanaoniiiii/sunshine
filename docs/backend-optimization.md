# Android 串流后端优化（v2026.10.12.1）

基于已发布提交 `049fa3a14510eda04fe9337bd4e23455e5fdf924`。参考项目固定为：

* [Foundation Sunshine f0ec742](https://github.com/AlkaidLab/foundation-sunshine/tree/f0ec742292a09bd8a23c77b990716bebd6ec9166)：`src/stream.cpp`、`src/streaming/{bitrate,fec}.cpp`、`src/perf_recorder.cpp`。参考每会话预算、发送节奏与分阶段统计。

本地真机复测发现旧原生库的多个编码线程竞争同一个 PCM 队列，第二客户端加入后第一客户端永久静音。逐会话音频分包、有限队列、退出唤醒和 JNI 线程生命周期已纳入本项目 Android 后端；当前原生引擎直接使用官方 Sunshine 核心与本项目平台适配。源码版本、依赖哈希、补丁与两种 ABI 构建脚本见 [原生构建说明](../native/README.md)。桌面平台特有的 HDR、GPU 驱动和虚拟显示代码没有直接套用到 Android。

## 已实现

| 流程 | 原行为 | 新行为 |
| --- | --- | --- |
| 多客户端帧率 | 最后一个连接覆盖全局 FPS；捕获回调不限制送帧 | 每个 Surface 独立期限，按客户端请求和配置上限送帧 |
| 高速捕获/慢编码 | 捕获回调与补帧分别绘制，可能形成突发 | 合并待处理回调，只保留最新纹理、一个待执行送帧任务；错过期限跳过过期时段 |
| 静态画面 | 补帧采用壁钟，与捕获时间戳混用 | 补帧和正常帧都使用单调时间；每个 Surface 的提交时间戳严格递增 |
| EGL | 未明确要求可录制及 Pbuffer/Window 支持 | 请求 `EGL_RECORDABLE_ANDROID` 和两个 Surface 类型；防止旧线程清理新资源 |
| 音频 | Binder 线程直接读 AudioRecord；录音持续保留，可能积压旧音频 | 专用音频线程读取，有限长度的立体声 PCM 环形缓冲，溢出丢最旧数据；空闲停止录音并清空 |
| 原生多端音频 | 多个 Opus 编码线程竞争共享 PCM 队列，退出可能令其他客户端静音 | 单次捕获广播给逐客户端分包器和队列，按各自包长编码；退出先移除订阅、停止队列并唤醒编码线程，再等待线程结束 |
| JNI 生命周期 | 嵌套回调无条件 detach，可能使视频线程的 Surface 引用失效 | 只释放当前作用域自行附加的线程；编码器启动后创建虚拟显示，宿主同步解绑 EGL 后才停止编码器 |
| 断开重连 | 旧遥测线程可能跨越新会话继续运行 | 世代标记使旧线程退出，取消 ping 并回收子进程 |
| 后台资源 | 串流无专用 Wi-Fi/CPU 锁 | 有连接时保持 CPU 唤醒，按设置请求 Wi-Fi 低延迟，全部断开或服务退出时释放 |
| 指标 | 默认 FPS/延迟掩盖故障，UID 总发送量被均分为每客户端码率 | 保留实测零值；未知 RTT 为 `null`，五秒后过期；总发送量明确包括音频、FEC 与 API，未知会话码率和编码格式不再伪造 |

音频缓冲以 48kHz 立体声 float 计量（每毫秒 96 个 float），读给原生层时只返回完整包。为容纳一个客户端协商的完整包，实际容量可高于配置值；诊断接口报告实际上限。Binder 读只等待有界时间，最长 110ms，不直接调用 AudioRecord。缓冲不代表完整音频链路延迟，系统 AudioRecord、原生队列和客户端仍有各自缓冲。

## 新增设置和接口

以下设置在 UI 和 `/api/config` 中可用，保存后作用于宿主串流流程：

| 配置项 | 默认值 | 范围/意义 |
| --- | --- | --- |
| `max_stream_fps` | `240` | 15–240；每客户端有效 FPS 为请求值与上限的较小值，不修改原生编码器的协商格式 |
| `repeat_frames` | `true` | 静态画面按各客户端帧率补帧，保证静止画面与新连接有输入 |
| `audio_buffer_ms` | `40` | 20–100；宿主 PCM 排队上限，溢出优先保留最新完整立体声样本 |
| `wifi_low_latency` | `true` | 仅有串流时请求系统低延迟 Wi-Fi 模式，效果取决于系统、屏幕状态和设备，可能增加耗电 |

* `GET /api/diagnostics`：捕获 FPS、各客户端请求/有效/实测 FPS、成功送帧/重复帧/合并帧/失败次数、慢送帧次数、最近 256 次成功送帧的 GPU handoff P95/最大值、捕获帧年龄、音频排队与溢出量、各项能力边界。
* `GET /api/encoders`：设备报告的 H.264/HEVC 编码器名称、硬件标记、分辨率对齐与上限、低延迟能力标记。宽高上限不意味着能同时使用该宽高，更不表示原生引擎已使用该编码器特性。

合并帧是宿主主动选择最新画面的计数，不能解释成网络丢包率。`encode_time_ms` 为兼容保留，等于新增的 `gpu_handoff_ms`，只包含绘制与 Surface swap，不是 MediaCodec 出帧延迟。`network_latency_ms` 是检测到的对端 ICMP RTT，不能代表视频传输/解码延迟，也不能准确关联所有会话。网络丢包与硬件编码延迟没有原生反馈，保持未知。

GPU 统计累计到捕获生命周期结束（引擎空闲恢复保留捕获）。P95 是最近 256 次成功 handoff 的滑动样本；失败及慢 handoff 另有计数。客户端码率保留为 `0` 表示未上报，UI 显示未上报；编码模式变更需空闲重启后生效，不能仅凭 HEVC 开关断言正在使用 H.265。

## 后续原生层优先级

`app/src/main/jniLibs` 保留可直接构建 APK 的原生库；`native/` 中的固定来源和补丁可从源码重建它们。现有 JNI 仍未提供动态码率、FEC 或逐会话编码延迟反馈。`min_bitrate`、`max_bitrate` 等旧配置未通过这些接口改变运行中的编码码率；本次没有添加没有实现支撑的 FEC/码率开关。

| 优先级 | 建议 | 实现和验证前提 |
| --- | --- | --- |
| 已完成 | 原生来源固定和构建 | 固定官方 Sunshine commit、子模块、NDK、Boost/OpenSSL 哈希；保留宿主独立 engine 与断开恢复逻辑，逐 ABI 从源码构建 |
| 已完成 | 原生音频队列与包长隔离 | 每客户端按协商 packetDuration 重组，原生队列最多 40ms 或一个更长协商包；这与宿主 PCM 缓冲分别计量，并非端到端音频延迟上限 |
| P1 | 编码前丢旧帧、编码后队列预算 | 编码前允许丢最新纹理之外的旧帧；编码后的参考帧不能随意丢弃，否则需 IDR 恢复机制 |
| P1 | 逐客户端动态码率与自适应 FEC | 移植 Foundation 的 `streaming/bitrate` 和 `streaming/fec` 预算思路；提高冗余前降低视频码率，维持总链路预算；增加 JNI 与原生反馈 |
| P1 | UDP 发送节奏与有界批次 | 采用 Android 逐数据报发送与真实统计，按链路预算 pacing；不能用更大 socket 缓冲掩盖排队延迟 |
| P1 | 慢编码器隔离 | `eglSwapBuffers` 仍可阻塞共享 GL 线程；进一步采用可验证的 EGL fence/独立提交线程或原生队列背压，不能仅靠下一帧降频解决当前阻塞 |
| P2 | 逐会话链路统计、手动 IDR 与断开 | 增加已协商 codec/bitrate、捕获到编码输出时间、Moonlight loss/RTT/FEC 与会话控制 JNI；避免宿主猜测与全局进程重启 |
| P2 | 单应用/扩展显示串流 | 按 Android 平台显示接口设计；需要 Android 14+ 单次授权、多显示输入坐标和 OEM 差异实机验证 |

## 回归与对比测试

JVM 测试验证不同 FPS 客户端、调度停顿不追赶、配置边界与旧文件兼容、音频溢出/环回/清空/完整包。它们不证明硬件送帧、Wi-Fi 或公网丢包效果。

本地使用原签名覆盖安装，在上一版和本版上按同一网络、分辨率、客户端码率及编码模式对比：

1. 两台安卓设备及电脑 Moonlight：同一宿主分别连接 30/60（设备允许时 120）FPS，记录客户端统计与 `/api/diagnostics` 的目标 FPS。改变连接顺序应不改变另一客户端的送帧上限。
2. 动画画面与静态画面各五分钟，对比 GPU P95/max、慢送帧、捕获年龄、客户端 dropped frames、接收 FPS/网络延迟。关闭补帧后检验静态连接与输入响应，再恢复默认。
3. 按用户要求播放抖音验证声音，不使用合成测试音；连续断开重连至少十次，检查声音恢复。没有同步标记或外部测量时，不宣称精确测得音画偏移。制造 CPU 负载并观察排队不超报告容量，溢出计数增加时优先保留最新数据。
4. 按原发布断开回归：单端退出保留其他端，反复打开 UI，全部退出只换 engine PID，恢复窗口快速重连；音频/CPU/Wi-Fi 资源应随最后一个会话退出释放。
5. 在可控路由器或 Linux 网络桥上分别注入延迟、抖动、随机丢包与带宽限制，保留 Moonlight 接收统计。本次未修改原生 FEC，不能宣称已修复链路丢包或已实现自适应码率。
6. 查询 `/api/encoders`，在 Snapdragon/MediaTek、Android 10/14+ 检查可录制 EGL 配置与 H.264/HEVC；Wi-Fi 开关效果必须实测，尤其后台及熄屏条件。

候选版本为 `v2026.10.12.1` / code `20261012`。只有使用历史签名并完成上述真机回归后，才发布 v7a、v8a 和通用 APK。云端候选签名与原发布签名不同，不应通过卸载或清除数据绕过。
