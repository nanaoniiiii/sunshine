# 逐会话网络反馈与自适应控制

`v2026.10.12.3` 扩展固定 Android 原生引擎。参考 foundation-sunshine 的逐会话码率预算思想，接入固定 Moonlight common-c 的 `SS_FRAME_FEC_STATUS` 协议；屏易连原有的发送、FEC 与控制通道继续使用，不替换客户端协议。

## 反馈和发送

原生控制通道接收 21 字节的大端 FEC 报告，校验 shard 数量、接收数量和多块索引。仅接受宿主近期发送的帧，最近 256 个帧/块键用于去重。报告包含恢复或未完成的块，采用尽力传送；没有报告不等于零丢包，不能把这些计数转换为全链路丢包率。

`GET /api/diagnostics` 的每个 `video` 会话新增：

- `control_rtt_ms`：ENet 可靠控制包的 RTT，超过五秒未更新为 null；不是视频端到端延迟。
- `fec_percentage` / `pending_fec_percentage`：当前与等待编码器接受的 FEC，pending 为 -1 表示没有待应用改变。
- `fec_reports`、恢复/不可恢复块计数、报告中的缺失数据包数、重复和拒绝计数、最近报告年龄。
- `nominal_video_fec_budget_kbps`、`control_ceiling_kbps` 与自动状态。

UDP pacing 从固定的 800 Mbps 改为每会话的编码/FEC 预算，使用分数纳秒期限，不将低码率取整成零。批次限制为每毫秒预算且最多 16 个包，每会话保留独立期限。发送节奏计入包头估计，额外预留至多 500 kbps（低预算时至多 10%），对应上游协商预留的包头余量。预算不是测得的链路带宽，也不包含独立音频通道；最小 parity shard 及整包取整仍可能使实际冗余比例高于名义比例。

排队帧持有会话引用，退出时不再发送该会话的剩余帧；pacing 等待每十毫秒检查退出。广播引用由会话 join 线程释放，避免最后一个帧引用在发送线程上销毁会话时自我 join。

控制通道补充截断、加密长度和明文长度校验；引用帧失效请求在不支持该原语的 Android MediaCodec 上转为 IDR 恢复。

## 控制入口

沿用会话 ID：

| 请求 | JSON 请求体 | 行为 |
| --- | --- | --- |
| `POST /api/runtime/sessions/{id}/fec` | `{"percentage":25}` | 0–35；手动请求关闭自动模式 |
| `POST /api/runtime/sessions/{id}/adaptive` | `{"enabled":true}` | 为当前会话启用反馈控制 |
| 同上 | `{"enabled":false}` | 停止自动调整，保留当前码率与 FEC |

手动设置码率也会关闭自动模式。重新连接的会话默认关闭自动模式；当前 FEC 不持久化为下一会话的设置。

FEC 调整先计算编码器目标，确保名义视频加 FEC 预算不增加，并遵守配置下限。编码器接受目标后才提交 FEC；拒绝时保留旧 FEC，并显示 `driver_rejected`。无可行预算时返回冲突。请以诊断中的已应用结果为准，HTTP 接受仅代表请求进入队列。

## 自动策略与边界

这是默认关闭的实验性反馈策略。收到有效丢失报告时，最多每两秒降码率 15%，可恢复块将 FEC 增加 2 个百分点，不可恢复块增加 5 个百分点，自动增加上限 35%。不超过协商视频预算，也不低于配置下限。提高冗余前等待编码器接受码率目标。

持续二十秒没有新的丢失报告，并且视频仍在输出、可靠控制 RTT 小于等于 100ms 且更新时间不超过五秒时，可每五秒谨慎探升约 5%（至少 100 kbps），同时将冗余缓慢恢复到连接初始值。这个探升条件是启发式；安静的报告通道不证明视频完全无丢包。没有新鲜 RTT、无视频输出或上一目标未被驱动接受时不探升。

原生测试覆盖解析、过期/重复报告、序号环回、预算、降码率、冷却、驱动拒绝与探升。实际弱网收益必须用受控丢包和限速进一步对照；只在稳定局域网切换控制，不能证明弱网改善。

## v2026.10.12.4 修订

孤立损失观察、持续队列/RTT 压力回退、更严格的探升条件，以及防止大关键帧与有界队列互相触发恢复循环的有限 IDR 发送加速，见 [队列与编码器说明](queue-encoder-controls.md)。本版诊断补充实际接受的 UDP payload 和分阶段发送耗时。自动控制继续默认关闭。
