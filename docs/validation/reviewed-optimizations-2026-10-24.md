## HTTP 状态处理

对正在连接的测试客户端执行一次保持原名称的保存，返回成功；保存前后配对列表完全一致。没有删除客户端或修改证书。

另发起一个只传入部分请求体的配对重命名请求，保持其未完成时读取客户端列表。列表在约 `0.015 s` 返回，证明实机上慢请求体没有占住状态锁。随后补齐故意无效的 JSON，请求返回 HTTP 500；错误响应可由 JSON 解析器正常解析，`status=false`。这项测试验证 HTTP 服务的锁范围和错误编码，不代表 Java 锁能协调原生引擎的跨进程文件写入。

## 实际画面与运行样本

已经观察电脑接收端的实际渲染，Sunshine 首页、串流卡片、设置导航与锁屏错误提示显示完整。连接请求为 `2560×1440 / 60fps`，主屏处于竖屏并启用自动旋转，实际编码为 `1440×2560`，不能把请求尺寸当作这时的编码尺寸。

主屏样本实际编码约 `59.7–60.4fps`，电脑覆盖层也显示约 `60fps`。两次记录之间编码帧数从 `8426` 增长到 `9526`，视频队列丢帧、发送错误、无效缓冲均为 `0`，提交超时及 Surface 失败也为 `0`。静止画面的源帧较少，重复帧开启；这些读数不证明原画面每秒刷新 60 次，也不作为本轮优化带来 FPS 提升或端到端延迟降低的证据。

音频采集处于运行状态，40ms 有界队列正常返回。累计溢出丢弃出现过 30ms，两个取样点之间没有继续增加；未把这一状态查询当作听感或音画同步验收。崩溃缓冲样本中未发现 Sunshine 的进程崩溃记录。

## 锁屏与桌面创建边界

本轮建立了真实锁屏前提：调用前系统 `Keyguard showing=true`，随后请求三星原生 DeX。接口约 `0.485 s` 返回 `status=false`，明确提示“请先解锁主机，再确认三星 DeX 启动；无需重置 Sunshine 授权”。电脑画面同时显示这条提示，后续虚拟屏状态为未创建、非 busy，输入服务仍就绪。这补齐了上一正式版验证中未建立锁屏条件的前置检查。

已请求用户正常解锁手机，等待继续候选版的原生 DeX 创建、普通 Sunshine 虚拟桌面、默认主屏息屏和接收端输入测试。锁屏下的鼠标滚轮尝试未观察到页面滚动，不计为通过。当前没有连接实体手柄，不把旧版手柄操作验收转记为候选版实测。

桌面与息屏三条路径在 `v2026.10.23.3` 的[全新安装验证](fresh-install-permissions-2026-10-23.md)中实际通过，本轮没有修改其实现；这仍不能替代候选 APK 的对应创建检查。候选尚未作为新正式安装包发布，官网继续提供上一正式版。

本轮已结束自建 Moonlight 测试进程并移除专用 ADB 转发。收尾时客户端数为 0，未遗留虚拟屏／DeX，输入适配器仍就绪；配置恢复原 `screen_off / sunshine`，除版本号外与升级前一致，全局强制桌面值为原 `1`、USB 保持亮屏值为原 `0`、主屏 override 保持 `1080×2400`。手机保留已安装的候选版。
