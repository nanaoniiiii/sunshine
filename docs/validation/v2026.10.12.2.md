# v2026.10.12.2 本地发布验证

2026-10-12，版本 `v2026.10.12.2`，`versionCode=20261013`。本轮按用户要求仅使用一台 OPPO Android 宿主和 Windows PC Moonlight 单连接，双端静音，使用无音频代码的 Canvas 小球；没有音频播放或音频效果测试。

- `:app:assembleRelease :app:testDebugUnitTest :app:lintRelease` 成功；22 个 JVM 测试，0 失败/错误/跳过；lint 0 错误、24 警告。
- 新增视频控制台测试分别以两种 ABI 在真机运行通过：码率预算、30 FPS、输出范围、P95 有界窗口、JSON 转义、部分批次进度、会话 ID/退出回调、命令合并与驱动失败重试策略。没有重新运行旧音频实测。

## 真机回归

宿主 OPPO PDEM10、Android 11；PC Moonlight 6.2.46。所有安装均覆盖升级，保留数据、配置和既有配对。

| 检查 | 结果 |
| --- | --- |
| Shizuku 授权识别 | 修复前已授予应用权限但 Provider 因 shell 缺少 INTERNET 拒绝 Binder；改为官方 Provider 权限后界面识别授权，输入绑定成功 |

| HEVC 720p30 | 请求和编码器配置均为 30 FPS，实际约 30 FPS；Moonlight 显示约 30.1 FPS、丢包 0%；没有强制升到 60 FPS |

## 边界

本轮完整串流只覆盖 OPPO 的 arm64-v8a 和 PC 单客户端；v7a 视频逻辑通过真机原生控制台测试，没有本轮 v7a 完整串流或多客户端回归。Shizuku 修复针对 Provider 权限阻拦这一通用原因，尚未在更多新设备实测。本轮没有音频验证、受控弱网/丢包注入、实际 GSO 故障注入、自动网络码率、自适应 FEC或端到端延迟对照。批量发送修复有源码检查和部分批次模型测试，不应宣称已经实测所有网络失败路径。

原始日志、设备信息、配对数据与截图留在本地，只公开汇总。各诊断量的准确含义见 [原生视频控制说明](../native-video-controls.md)。
