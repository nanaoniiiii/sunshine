# v2026.10.31.2 更新下载验证

本版本合并“开机即连”和更新下载改进。开机、录屏恢复与占用等待的实机记录见 [开机即连验收](instant-connect-2026-10-31.md)。

## 下载实现

- 将新下载从系统 DownloadManager 队列迁移到应用自身的前台下载服务，旧任务的完成状态仍可读取。
- 大文件最多四路 Range 请求，严格校验 HTTP 206 和 Content-Range；不支持 Range 时降级为完整文件请求。
- 同版本、ABI、大小和摘要的分段保留断点。暂停会中断网络，随后继续读取已保存的分段；切换官方来源顺序不会丢弃合法断点。
- 连续低速或请求失败时，仅尝试官网固定版本文件与本项目 GitHub 原始附件；不引入第三方下载代理。
- 显示实际字节、平均速度和来源，支持暂停、继续以及明确重新下载。下载服务和采集服务在同一进程，避免 Android 13 上新的 dataSync 兄弟进程导致录屏被回收。
- 拼接时核对大小和 SHA-256，安装前再次核对 APK 的摘要、包名、版本和签名；校验失败不提供安装。
- 更新清单请求设置单次请求超时及整个备用检查链的截止时间，避免失败线路造成长时间无反馈。

测试文件为公开的 v2026.10.30.1 arm64 APK，7,341,302 字节，摘要 `8218f979bfd4791b7347ff55d52f3e52adef63bcd764b12cae4f628fe5236058`。

- 平板系统 curl 从官网完整收到文件，用时 4.080 秒，响应为 HTTP 200、CF LAX、缓存命中。
- 相同官网文件的 Range 0–1023 返回 206 与正确 Content-Range，实际 1,024 字节摘要与整包前缀一致。
- 将本次真实编译的未混淆下载核心加载到平板执行，四路完整下载并验证摘要，用时 2.991 秒。该探针运行在 shell UID，验证 Android 上真实下载实现及传输完整性，不冒充应用 UI 的升级耗时。
- 平板当时直接访问 GitHub 的 TLS 连接失败，因此保留官网主源，GitHub 作为可用网络下的备用来源。

此时官网直接传输正常，不能据此声称已经复现或解释所有历史应用内慢速情况。此前 2026-10-22 的慢线路样本仍保留。本次改动增加下载自身的分段、续传和有限换源能力，不保证所有网络的固定下载速度。
