# 串流显示模式、启动与桌面返回验收

版本：`v2026.10.30.1`，versionCode `20261044`。设备为 S20+ SM-G986U1 与 Tab S7+ SM-T970，均为 Android 13；接收端为 Windows Moonlight。本文分别记录实现、实际设备样本和未覆盖范围。

## 首页“默认／全屏”

“串流状态”标题右侧始终显示双切选择，没有客户端或服务尚未开启时也可预选。选择同步提交到应用私有持久存储，与临时显示恢复记录分开；结束连接或清理恢复记录不会清除选择。设置页将分辨率和比例的入口统一指向此处，旧配置字段保留以兼容已有配置。

- 默认：保留／恢复主机原有逻辑分辨率、旋转策略和已有 override，按主机当前像素尺寸采集和编码。硬件 4:2:0 编码要求偶数尺寸时，只补齐一个像素，不改主机分辨率。
- 全屏：使用 Moonlight 的原始请求宽高调整显示，并同步采集窗口。读取原生会话的 `requested_width`／`requested_height`，避免把旋转后、已变化的编码尺寸误当成请求。
- 串流中切换会重新配置编码 Surface，保留会话与配对；最后一条连接结束后恢复原显示设置。模式选择本身继续保存。多端时先到的连接决定主机尺寸，后来连接不抢占；原生编码器保留各客户端自己的请求尺寸。
- 普通第二屏可在原显示 ID 上调整尺寸和采集 Surface，不为切模式重建整个桌面任务。原生 DeX 的接口也支持恢复原 override，但本轮没有取得可用于最终复测的原生 DeX 会话，不能把普通第二屏计为三星原生 DeX 验收。

| 实机样本 | 显示／采集／编码结果 |
| --- | --- |
| S20+ 串流前选全屏 | Moonlight 请求 2560×1440；主机逻辑显示、采集与编码均为 2560×1440。 |
| 同一连接切默认 | 主机恢复原 `1080×2400` override，采集和编码均恢复为 1080×2400。会话 ID 保留。 |
| 同一连接再切全屏 | 再次输出 2560×1440，仍是同一会话；该取样的队列丢帧和发送错误均为 0，不代表所有切换全程零丢帧。 |
| S20+ 普通系统第二屏 | 同一 Display 19 在 1080×2400 与 2560×1440 间切换，采集与编码匹配；此样本是 One UI 次级主页，不是原生 DeX。 |
| Tab S7+ 默认 | 原有 override 为自然方向 1752×3893，当前横屏源为 3893×1752；实际编码为偶数对齐的 3894×1752，Moonlight 收到真实画面。 |
| Tab S7+ 默认／全屏往返 | 同一连接在 3894×1752 与请求的 2560×1440 间切换成功。结束后恢复原 1752×3893 override。 |

本轮检查了手机横竖屏、平板大屏和接收端实际画面。“默认／全屏”位于标题右侧，未连接时可见；没有图标、文字相互覆盖。项目是原生 Compose，没有 dev server；当前环境缺少 AGENTS 指定的 browser-harness 和 vision.py，因此采用 ADB 真机截图及实际 Moonlight 窗口做视觉检查，没有用源码推断渲染结果。

## 实验室：开机自动启动与保活

新增两个独立持久设置：

1. **开机自动启动服务**：默认关闭；开启后，在系统 `BOOT_COMPLETED` 或应用自身 `MY_PACKAGE_REPLACED` 通知到来时，尝试启动 Sunshine 前台服务。
2. **服务常驻与异常恢复**：默认开启，延续此前 `START_STICKY` 行为；关闭后使用 `START_NOT_STICKY`。调整时向现有服务发送开始命令更新恢复策略，不中断已有串流。主动停止服务仍会正常停止。

S20+ 已验证覆盖安装后无需打开 Activity 即恢复服务，并保留全屏选择。随后实际重启，boot ID 改变。最初 110 秒观察窗口内状态接口尚未出现；后续系统日志明确记录 `BOOT_COMPLETED` 触发启动，随后出现 HTTP 服务监听及原生引擎连接，早于本轮手动打开 Activity。开机选择仍为全屏。这个样本不能用于承诺固定启动耗时。

本轮没有为自启测试额外授予系统签名权限、安装 Root 模块，或修改设备后台策略。设备已有的授权管理器状态影响可用能力，不推广为全新设备的永久授权保证。该功能是普通应用前台服务，不会把 APK 变成系统服务。强行停止、权限撤销和厂商后台限制仍可能阻止启动；录屏授权不被保存为可跨重启复用的令牌。

平台边界参考：[Android 后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)、[MediaProjection 授权生命周期](https://developer.android.com/media/grow/media-projection)。服务自动启动与无需再次确认录屏是不同能力。

## Sunshine 桌面：返回位置与图标

本次修复了三处导致复位／重载的路径：

- 普通 HOME 返回此前传入 `apps`，并在新 Intent 中重置栏目、焦点和刷新计数。现在使用 `resume`，恢复原栏目、选中应用、操作按钮和滚动位置；明确选择“应用／最近任务／控制”时仍按所选入口导航。
- 桌面启动此前使用 `MULTIPLE_TASK`。现在针对 Sunshine 桌面使用 `NEW_TASK | SINGLE_TOP`，复用已有 HOME 任务；还通过可保存状态和按显示 ID 的会话快照覆盖 Activity 重建。
- `onTrimMemory` 先前把普通 `UI_HIDDEN` 也当作低内存，清空全部图标。现在普通切应用不清理，只在真实内存压力时回收。缓存由 12 项改为 32 MiB 预算，移除生成的晕染位图；已缓存图标同步显示，不先置空等待协程。应用列表复用缓存，主动刷新和包变化才重新读取。

Tab S7+ 的实际第二屏 Display 26 验证：应用栏移动到非首项后，主页返回保留选中项及滚动位置；从“控制 → 声音设置”打开系统“声音和振动”，系统返回后仍在声音设置。再次打开后用 HOME 返回，也恢复声音设置，再按下键到系统设置。前后桌面 ActivityRecord 和任务 ID 保持相同。原生 HOME 的守护回收在应用启动保护期内可能短暂显示系统主页，这个系统方向键样本不代表实体手柄全部重新验收。

图标周围背景改为分析可见外边缘：逐行、逐列取首尾不透明像素，去重后统计近似颜色，采用出现最多的色组。透明边距和图标内部不参与投票；只平均胜出组内的微小色差，不把其他色混进背景。整屏填充此色，不再生成多色延伸图或边缘模糊过渡。右侧保留原图标，原有左下角自然阴影和控制页文字底层保留；浅色背景的大标题改用深色字。
