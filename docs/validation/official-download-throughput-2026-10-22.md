# 官网安装包持续下载与发布同步验收

记录日期：2026-10-22。测试跨越 10 月 21 日晚至 22 日凌晨，目标文件为公开版本 v2026.10.21.2 的 arm64 APK，大小 7,085,884 字节。

## 结论

手机当前网络访问官网的持续传输确实很慢，不能将问题归结为等待首包或官网查询 GitHub。手机在缓存命中的情况下，180 秒只收到 236,265 字节；首包后的平均传输约 1.34 KB/s。改成发布时推送官网副本后，同一网络仍然很慢，60 秒收到 131,329 字节，首包后的平均传输约 2.78 KB/s。因此本次没有解决这条访问线路的慢速。

同一台手机通过一条临时测试连接改走电脑已有出口后，45.204 秒完整收到同一文件，SHA-256 与 GitHub Release 一致。手机到 Cloudflare 分发节点的访问路径差异是主要线索，尚未定位到具体运营商互联、丢包或其他链路环节；不能据此声称 Cloudflare 对该文件设置了限速。

## 实测

以下 KB/s 按 1000 字节计算。“主体速率”用收到字节数除以总时间减首包时间，专门观察开始下载后的持续传输。超时样本是未完成文件，不能当作完整 APK。

| 场景 | 总时间 | 首包 | 收到字节 | 总平均 | 主体速率 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 手机原网络，原服务 | 180.001 秒 | 4.184 秒 | 236,265 | 1.31 KB/s | 1.34 KB/s | 180 秒超时，HTTP 200，未完成 |
| 手机原网络，推送模式部署后 | 60.000 秒 | 12.812 秒 | 131,329 | 2.19 KB/s | 2.78 KB/s | 60 秒超时，HTTP 200，未完成 |
| 同手机，经电脑已有出口 | 45.204 秒 | 2.513 秒 | 7,085,884 | 156.75 KB/s | 165.98 KB/s | 完整下载，摘要一致 |

两次慢速样本均为版本固定 URL、零重定向，响应 `CF-Cache-Status: HIT`，节点标识 LAX。后一份响应另外含 `X-Sunshine-Download-Source: cache`，表明即使安装包已经命中缓存，持续下载仍很慢。手机电源状态为 Awake、设备空闲状态 ACTIVE，TCP 接收缓冲自动调节开启，未将休眠推断为本次慢速原因。

补充样本：电脑当前出口下载旧版同等大小官网 APK 约 359 KB/s；下载 GitHub 的本版 APK 约 442 KB/s。手机直达 GitHub 的一次测试在 TLS 握手阶段失败，不能把 GitHub 直链当成该手机网络上已验证的快速替代。www 域名的 1 MB 范围请求也未通过，45 秒无数据；IPv6 请求未连接成功。这些结果只适用于本次设备和网络，不能推广到所有地区。

对照连接仅在 curl 的单次请求中使用电脑已有出口，经临时 ADB reverse 端口转发；未更改手机系统代理或 DNS。测试端口已在 finally 中移除，最终 reverse 列表为空，系统 http_proxy 保持 null。本地 workerd 预览已停止。

## 发布同步已完成

- GitHub 已公开发布 [v2026.10.21.2](https://github.com/nanaoniiiii/sunshine/releases/tag/v2026.10.21.2)，三个 APK 和 SHA256SUMS.txt 的线上大小、摘要与本地一致。
- GitHub Actions 的 [官网同步工作流](https://github.com/nanaoniiiii/sunshine/actions/runs/39631463367) 已实际成功运行，三个 APK 均复制至官网 KV 存储，摘要与 Release 一致。
- 网站访客请求不再查询 GitHub。更新清单、latest 别名和安装包从已部署静态基线或已推送的官网副本读取；公开响应核对 `X-Sunshine-Update-Mode: push`、版本 v2026.10.21.2。
- 同步端先核对三个公开附件的大小和 SHA-256，再逐个签名上传；服务器验证所有副本后才更新官网清单。只保留最近三组动态副本，GitHub 原始发布文件不删除。
- 仓库只保存用于官网安装包发布的专用签名密钥，不保存个人 Cloudflare OAuth。密钥通过 stdin 配置在 GitHub Secrets 和 Worker Secrets，未写入本地文件或输出。
- 首轮任务的上传和提交已成功，但额外的 Python 匿名公网复核遭 Cloudflare 403/1010，导致任务误报失败。工作流现以签名发布接口的校验回执判断完成；没有伪装浏览器身份或降低站点防护。第二次实际执行成功，另外核对了官网清单和存储记录。

当前生产 Worker 为 nanaoni-tech，版本 `b3e2dd1e-2554-4353-a01c-e2c554790e7c`，100% 流量。发布前版本为 `88e4ca02-cefa-4f1f-b9d6-013c206f0c1c`，保留可回滚。根域名和 www 均仍绑定同一生产 Worker、enabled=true。未修改 DNS、路由或域名绑定，前端静态页面保持原版。

## 验证范围与后续边界

19 项官网服务测试通过，覆盖签名、过期或篡改请求、摘要错误、三份包齐备才发布、幂等、版本回退、撤回、保留策略、无访客触发 GitHub 请求、Range、条件请求与错误路径。实际本地 workerd 完整读取 APK 的摘要正确，断点请求得到 206 和正确字节片段；实际 GitHub Actions 与生产存储同步成功。

自动复制与取消官网轮询已经完成。要改善本次手机网络下的大文件持续速度，需要进一步选择该网络可达性更好的安装包分发线路；本次没有更换供应商、购买加速服务或把所有网络的下载速度标成已修复。

原始响应头、下载样本、部署与域名核对记录位于被忽略的 work/desktop-20261021/，手机测试文件位于 /data/local/tmp/；不把设备抓取或凭据上传仓库。
