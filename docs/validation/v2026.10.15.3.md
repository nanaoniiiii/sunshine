# v2026.10.15.3：DeX 实验入口与第二屏刷新率请求

日期：2026-10-15。版本代码：20261026。

## 实现

- 设置列表最下方新增「实验性功能」按钮，进入独立页面。提供「第二屏启用三星 DeX」和「请求高刷新率」，沿用自动保存。
- 三星 DeX 默认关闭。开启后，创建第二屏时尝试三星系统第二屏桌面及原厂 Desktop Launcher；检查该显示中任务的 `Configuration.semDesktopModeEnabled`。仅成功启动一个 Activity 不作为 DeX 已启用的依据。未确认 DeX 模式时回退到原有全屏 Sunshine 桌面。
- 高刷新率请求使用接收端请求帧率与 Sunshine 帧率上限中的较小值。在提供接口的系统上，通过 `VirtualDisplayConfig.Builder.setRequestedRefreshRate()` 和 `DisplayManager.createVirtualDisplay(VirtualDisplayConfig)` 创建显示；旧系统保留兼容创建路径。
- 实验页面及 `/api/virtual-screen` 分别记录目标刷新率、系统实际刷新率、接口支持情况与 DeX 运行结果。显示模式变化时更新实际刷新率；串流补帧不作为显示刷新率。
- 用户显示服务协议更新为 3，防止覆盖安装后调用旧接口。

接口依据：[Android VirtualDisplayConfig.Builder](https://developer.android.com/reference/android/hardware/display/VirtualDisplayConfig.Builder#setRequestedRefreshRate(float))、[DisplayManager](https://developer.android.com/reference/android/hardware/display/DisplayManager#createVirtualDisplay(android.hardware.display.VirtualDisplayConfig))。本地 Android 34 SDK 的公开签名也已核对。

## 当前实机结果

主机：Samsung SM-G986U1，Android 13；接收端：OPPO PDEM10，Android 11，使用原有 Moonlight。请求 1440 × 3168、120 FPS。

- 设置底部入口、实验页面与运行结果均经过真实设备截图检查。DeX 开关切换后，API 读回 `experimental_samsung_dex=true`，覆盖安装后设置保留。
- 开启两个实验开关后，虚拟屏创建成功并继续串流。系统报告 `actualRefreshRate=60.0`、目标 120、`refreshRateRequestSupported=false`、`dexRequested=true`、`dexActive=false`，显示 Sunshine 回退桌面。
- `dumpsys desktopmode` 同时报告 `mDualModeEnabled=false`、`mDesktopDisplayId=-1`，与应用结果一致。
- 读取本机系统适配器发现：Android 13 的 `VirtualDisplayAdapter` 创建与调整模式都固定使用 60.0f；本机框架没有 `setRequestedRefreshRate`。仅提高串流 FPS 或修改应用配置无法改写这个系统实现。本次未宣称已解除这台手机的 60 Hz 限制，也未宣称成功启动原生 DeX。
- 退出实验第二屏成功，串流恢复主屏；`force_desktop_mode_on_external_displays`、`enable_freeform_support` 恢复为原值 0／1。
- 最终 APK 的显示控制器另做 shell UID 2000 冒烟测试：1920 × 1080、目标 120 Hz，创建独立显示 39，ImageReader 收到 45 个画面，返回实际 60 Hz、DeX 未启用及回退桌面；关闭显示成功。与手机串流测试的结果一致。
- Android 14 及以上的刷新率请求路径已按 SDK 接口实现；没有使用兼容的新系统设备验证真实 120 Hz 输出。
