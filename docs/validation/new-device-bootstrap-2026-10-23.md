# 新设备授权后的用户服务启动修复

版本：`v2026.10.23.3` / `20261040`。本轮设备为新接入的国行 S20+ `SM-G9860`，Android 13，Shizuku `13.5.3.r1037.64e7877`。之前的美版 `SM-G986U1` 和 OPPO 不在线，本文不沿用它们作为本补丁的实测证据。

后续已按用户要求撤销这台电脑 USB 信任、清除旧 Sunshine 授权，并完成最终包的全新首次安装测试：三种模式均有实际创建与 Moonlight 接收证据，见[清除旧授权后的首次安装验证](fresh-install-permissions-2026-10-23.md)。下方保留此前候选包与最终包的检查过程及边界。

## 故障与修改

旧版已获得 Sunshine 的 Shizuku 权限，shell 服务仍在，但三星后台策略阻止管理器 provider 启动，日志出现 `Restricted by policy: 2`、`provider is null` 和用户服务启动超时。输入适配器无法就绪，显示服务也无法绑定，因此普通虚拟屏和 DeX 都未进入真正的创建阶段。

仅打开管理器可临时使输入服务连接；仅将管理器 `RUN_ANY_IN_BACKGROUND` 设为允许之后，显示服务仍复现回调失败。修复在 UserService 绑定之前通过已授权的 Shizuku server 执行准备，不依赖需要被修复的 UserService：

- 根据 server 实际 `CLASSPATH` 中的 APK 与安装信息精确匹配当前 Shizuku／Stellar 管理器，不以“安装了哪个”猜测，也不修改其他管理器或应用。
- 解除该管理器明确存在的 `RUN_IN_BACKGROUND` / `RUN_ANY_IN_BACKGROUND` 限制，为该管理器与 Sunshine 添加完整电池优化豁免；没有关闭三星全局后台管理。
- 输入适配器异步等待准备完成后绑定，代际检查阻止停止后的旧回调重新启动；显示服务也等待同一份串行准备。无 Moonlight 客户端时同样执行。
- 相同 server Binder 共用一次准备，绑定超时后允许下一次重新检查。未知管理器或准备接口不可用时继续正常绑定，并保留可操作的失败信息。
- 修正创建失败时直接取 `cause.message` 丢弃上层说明的问题；管理器打开入口使用已识别的当前包。
- 原生 DeX 尚未运行且主机已锁屏时，启动接收端前立即说明需要解锁，避免在看不到系统确认的情况下等待三分钟；已运行的原生 DeX 仍按原流程采集。

## 实机结果

安装候选包前，将管理器恢复为最初的 `RUN_ANY_IN_BACKGROUND=ignore`，通过普通后台进程回收使其退出，原先也没有管理器电池豁免。安装后未手动打开管理器或修改其电池页面：

| 路径 | 实际结果 |
| --- | --- |
| 未连接 Moonlight 的服务启动 | 自动改为 `RUN_ANY_IN_BACKGROUND=allow`，管理器加入 device-idle user 白名单；新 shell 输入服务启动，适配器 `ready=true`、系统导航已连接。 |
| 默认 `screen_off` | 显示服务成功绑定，仍采集原主屏，`displayId=0`；SurfaceFlinger 物理面板 `powerMode=Off`，Windows Moonlight 实际显示主屏 Sunshine 页面，观察到约 60fps 接收。没有自动打开独立桌面。 |
| Sunshine 普通独立桌面 | 实际创建 2560×1440 / 60Hz 桌面并在 Windows Moonlight 显示；虚拟屏活动期间全局 Android 强制桌面值为 0，完整退出后恢复原值 1。 |
| 三星原生 DeX | 首次三星“立即开始”确认后，系统进入双屏 DeX，Moonlight 显示三星原生主页和任务栏。桌面 Display 2 的 `wm size` 为 Physical 1920×1080、Override 2560×1440，有效逻辑尺寸与编码输出均为 2560×1440；原生模式仍为 1920×1080 / 60Hz。静止桌面样本约 4fps，不把 60Hz 或配置 60fps 当作持续实际帧率。 |
| DeX 完整退出 | 本次 DeX 结束、Display 2 尺寸 override 撤销，全局强制桌面值恢复为 1。 |

截图和完整设备日志只保留在本地被忽略的测试目录，不进入仓库或发布包。

最终文本候选包追加复测：在 Sunshine 与管理器后台进程均已退出后启动 Sunshine，新的 shell 控制器自行绑定、系统导航就绪；新的显示服务成功完成默认息屏串流，并创建 2560×1440 的 Sunshine 桌面。再次尝试原生 DeX 时手机已自动安全锁屏，未能完成三星确认，该次等待超时已清理接收端；此前成功的原生 DeX 实测来自同版功能候选。随后补充的锁屏前置检查已构建、安装；最后一次重新启动 Moonlight 的命令被自动审批拒绝（仅返回 `blocked by policy`），未执行，因此此项未完成最终包实机复测，不把前述超时记录为 DeX 通过。

## 检查与边界

当前构建 205 项 JVM 测试通过，0 失败、0 错误；`lintRelease` 和 `assembleRelease` 成功。Lint 0 错误、50 条现有警告，包含 Compose 自定义检查版本不匹配而跳过的警告。新增测试覆盖错误上下文保留、活动管理器精确匹配／歧义跳过、限制状态解析及白名单完整匹配。

此修复解决本机实际复现的后台阻断路径。仍需正常启动 Shizuku、授予 Sunshine 权限和录屏许可；三星首次 DeX 的系统确认属于必要授权步骤。未知管理器、其他厂商独有的限制、缺少原生 DeX 的设备，以及重启后免 Root Shizuku 需重启服务的规则，没有被当作已解决或全部验证。未重做所有实体手柄操作与游戏兼容性验收，本补丁不修改映射逻辑。
